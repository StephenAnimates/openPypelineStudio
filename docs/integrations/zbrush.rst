Maxon ZBrush Integration
========================

Maxon ZBrush is a primary focus area on the openPypeline Studio roadmap. As the premier digital sculpting software for creature, character, and organic concept art, ZBrush plays an essential role in high-fidelity asset development.

Support Status & Target Specifications
--------------------------------------

* **Status:** Planned Priority (Roadmap Phase 4)
* **Target Versions:** Maxon ZBrush 2023, 2024, 2025+
* **Integration Archetype:** Script-Bridged & Subprocess (Archetype 2)
* **Communication Channel:** ZScript command generation and command-line execution
* **Module Path:** ``openpypeline/app/zbrush/``

Role in the Production Pipeline
-------------------------------

In the openPypeline workflow, ZBrush typically drives the initial sculpt and detailing stages:

1. **Base Mesh Ingestion:** Ingesting rough blockout meshes or base cages published from Maya.
2. **High-Poly Sculpting:** Artists sculpt multi-million polygon details, saving incremented tool files (``.ztl``) or project files (``.zpr``) in the asset's ``wip/`` directory.
3. **Decimation & Bake Staging:** Exporting decimated high-poly meshes and low-poly game cages (in OBJ, FBX, or USD format) to the asset's publish folders, preparing them for texturing in Adobe Substance 3D Painter.

Script-Bridged Architecture
---------------------------

Because ZBrush does not embed an internal Python interpreter, the openPypeline ZBrush adapter operates through an **external command bridge**:

.. code-block:: text

   +--------------------------+          +--------------------------+
   |   openPypeline Studio    |          |       Maxon ZBrush       |
   |   (Companion Launcher)   |          |      (Native Executable) |
   +------------+-------------+          +------------+-------------+
                |                                     ^
                | 1. Writes ZScript (.txt / .zsc)     |
                | 2. Invokes via subprocess           |
                +-------------------------------------+

ZScript Generation & Execution
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

To open a ZTool, the adapter creates a temporary ZScript file:

.. code-block:: text

   // Dynamic ZScript generated by openpypeline
   [IPress, Tool:Load Tool]
   [FileNameSetNext, "D:/Projects/film/scenes/assets/characters/hero/wip/hero_sculpt_wip_v0003.ztl"]

The adapter then triggers ZBrush using Python's standard ``subprocess.run()``:

.. code-block:: python

   import subprocess

   zbrush_exe = "C:/Program Files/Maxon ZBrush 2025/ZBrush.exe"
   subprocess.run([zbrush_exe, temp_zscript_path])

Supported File Formats
----------------------

.. list-table:: ZBrush Asset Formats
   :widths: 20 30 50
   :header-rows: 1

   * - Extension
     - Format Name
     - Description
   * - ``.ztl``
     - ZTool
     - Standard sculpting format containing 3D meshes and SubTools.
   * - ``.zpr``
     - ZProject
     - Complete ZBrush workspace (all tools, canvas, lights, materials).
   * - ``.obj`` / ``.fbx``
     - Export Geometry
     - Exported geometry for texturing in Substance Painter or retopology.

Concurrency & Advisory Locking
------------------------------

Because ZBrush runs outside of Python's memory space, openPypeline manages advisory concurrency through the companion launcher:

* When the user clicks **Open in ZBrush** or **Save ZBrush WIP**, the openPypeline launcher registers a file notice in ``<project_root>/.openpypeline/file_use/<hash>.use``.
* The companion launcher maintains the recurring heartbeat timer while ZBrush is active, ensuring other artists on the team receive advisory in-use warnings if they attempt to modify the sculpt.
